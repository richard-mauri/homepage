# Homepage architecture contract

Homepage is a small Go standard-library server and same-tab launcher. `main.go` embeds the `static/*` UI and handles configuration, health checks and the optional suite persistence endpoints. `LISTEN_ADDR` defaults to `127.0.0.1:8787` behind a separate Cloudflare tunnel. The private tunnel token, user credentials, logs and local build artifacts must never be committed. `devbuild.sh` runs tests and compiles native Intel/Apple Silicon binaries using Git-private local build counters; `homego.sh` restarts only Homepage and its tunnel when the owner chooses.

## Single twelve-hour Homepage account session
Homepage is the sign-in authority. A personal approved credential creates one 12-hour opaque Homepage session. The browser keeps only its temporary Homepage session ID in Homepage-origin `localStorage`; the approved personal credential is never saved. The Homepage-only cookie is host-only and does not authenticate sister-domain apps. Server-side storage, profile and role checks use the approved-credential digest and server-maintained session/bearer records. Session and handoff records are durably stored in `SUITE_DATA_DIR/auth/homepage-sessions.json` (0600, atomic replacement and file sync). The file stores SHA-256 hashes of opaque Homepage session IDs and app handoff bearers, not raw tokens or approved personal credentials. Each load preserves the original absolute expiration, and a restart must not extend it. The service refuses to start if existing session state cannot be recovered; failures to persist login, handoff, renewal or sign-out mutations fail rather than reporting false success. The storage directory must be a persistent, writable volume and should be protected and backed up appropriately. Roles and per-user storage authorization remain server-enforced.

NewsGo and MauriStocks require a transferable bearer for secure cross-origin calls, but **not an independent login**: on a signed-in launcher click, `POST /api/handoff/token` issues a bearer bound to the active Homepage session. Its expiration is capped by that session's original 12-hour expiration. A bearer cannot remain valid after the parent session expires or is signed out, and its originating credential is revalidated at each request. Every app handoff created under the same parent login is invalidated on `DELETE /api/session`, including bearers previously rotated through the legacy renewal endpoint. The old `-handoff-minutes` server flag is removed; the session lifetime is fixed at 12 hours. The legacy `/api/handoff/renew` endpoint is retained for backward compatibility with older app versions, but cannot extend a bearer beyond its parent session expiration. Updated apps remove the Renew control.

App handoff bearers are transmitted only in destination URL fragments, never URL query strings. The destination app removes the fragment from browser history and stores the bearer in its own origin's `sessionStorage`. Server validation is authoritative; the cached token is not a separate sign-in. Only trusted app origins may use the bearer-protected profile and revisioned per-user account storage APIs.

## Same-tab launcher and browser-only access
Homepage cards navigate to their configured HTTPS app destinations in the current browser tab. When the Homepage browser is signed out, the NewsGo and MauriStocks links explicitly navigate with `#suite_mode=local`, instructing the app to delete its cached bearer and enter browser-only mode without changing local settings. A handoff issuance failure also uses `#suite_mode=local`, not an old token. When signed in, a successful handoff includes `#suite_token=...`. The destination apps keep a valid bearer across ordinary reloads but must revalidate it with Homepage's API, which returns unauthorized after sign-out or expiry. Each app provides a native Back to Homepage link. No native blocking sign-in alerts, named tabs, new tabs or forced focus.

The changed launcher and auth contracts require coordinated NewsGo and MauriStocks client updates and Mac/Safari verification. Do not infer browser acceptance from CI alone.

## Authentication diagnostics

Homepage's optional `-trace` flag enables server-side auth HTTP result tracing and a same-origin `POST /api/trace` receiver for the browser's navigation/auth UI decisions. `/api/config` advertises only the trace-mode boolean. Every browser event is validated against fixed event and phase allowlists and a 16-character random page correlation ID. Logs go to the standard logger, which `homego.sh` redirects to `homepage.log`. Tracing never records raw cookies, approved credentials, session IDs, handoff tokens, usernames or private preferences. Session lookup outcomes are reported as a small fixed set (missing, expired, credential revoked, valid), and trace mode is off by default.
